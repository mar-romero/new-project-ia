# Definition of Ready

A task is ready when its writer can work without inventing material
requirements.

- [ ] Unique task ID, observable outcome and explicit out-of-scope.
- [ ] Risk level R0–R3 with reason.
- [ ] Testable acceptance criteria and relevant invariants.
- [ ] Relevant external contracts identified.
- [ ] Expected evidence/tests identified.
- [ ] Required human decisions resolved.

For R2/R3 also document meaningful failure modes, data/time assumptions,
security implications, rollback and a specification when cross-cutting.

Do not accept themes such as "improve reliability" as implementation-ready;
turn them into small, falsifiable work units.
