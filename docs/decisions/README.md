# Architecture Decision Records

ADRs preserve durable decisions and their evidence so future contributors do
not need to reconstruct the original constraints.

Create one for decisions that are cross-cutting, costly to reverse,
security-sensitive, vendor-dependent or likely to be reconsidered. Do not
create one for variable names, trivial refactors or temporary experiments.

Use the status flow `PROPOSED → ACCEPTED → SUPERSEDED → DEPRECATED`. Never
delete historical accepted decisions; supersede them with a new ADR.
