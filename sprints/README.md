# Sprint System

Sprints organize product milestones.

They are not giant implementation tasks.

A sprint contains several small T-XXXX tasks.

---

# Rules

One developer + Codex should prefer:

- small tasks;
- small diffs;
- frequent verification;
- independent reviews.

Do not create one task representing an entire sprint.

---

# Sprint Status

PLANNED

ACTIVE

COMPLETE

BLOCKED

---

# Completion

A sprint is complete only when its required exit criteria are met.

Incomplete optional items move to backlog.

Do not keep a sprint open merely because additional improvements are possible.
