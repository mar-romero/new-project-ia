# Task System

Every meaningful change should have a small, verifiable task record. The
repository is durable project memory; chat conversations are not.

Lifecycle: `BACKLOG → READY → IN_PROGRESS → REVIEW → DONE`, or `BLOCKED` when
evidence or a human decision is missing. Use `tasks/templates/TASK.md` to
define scope and risk. Move completed evidence to `tasks/done/` only after the
applicable Definition of Done is satisfied.

Keep one task to one observable outcome. Use `T-XXXX` identifiers; choose
ranges that fit the new product rather than inheriting another project's
numbering scheme.
